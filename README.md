# NetworkGuardian

An anomaly-based Intrusion Detection System (IDS) for IoT networks, running
entirely on the **edge** — a Raspberry Pi 5 gateway. Traffic is captured,
turned into flow features, and scored by a lightweight autoencoder that was
written **from scratch with NumPy only** (no TensorFlow / PyTorch / Keras).
The model is trained exclusively on *normal* traffic, so it flags previously
unseen and zero-day anomalies as high reconstruction error — no attack
signatures required.

## How it works

```
IoT devices ──▶ wlan1 (hotspot)                Raspberry Pi 5
                    │
                    ▼
              Scapy sniffer  ──▶  10-second windows
                    │
                    ▼
        9-feature extraction (per window)
                    │
                    ▼
          Min-max scaling  ──▶  Autoencoder (9-6-9)
                    │
                    ▼
      reconstruction error (MSE)  ──▶  threshold?
                    │                        │
              below │                        │ above
                    ▼                        ▼
                 log "normal"          log "ANOMALY" + email alert
```

The Pi acts as a gateway: `wlan0` is the uplink to the home router, `wlan1`
is the IoT hotspot (`hostapd` + `dnsmasq`), and `iptables` NAT forwards
hotspot traffic to the internet so every packet passes through the Pi where
it can be observed.

### The 9 features (per 10-second window)

| # | Feature | Meaning |
|---|---------|---------|
| 0 | `packet_count`     | total packets — spikes suggest floods |
| 1 | `avg_size`         | mean packet size (bytes) |
| 2 | `std_size`         | packet-size variability |
| 3 | `unique_dst_ips`   | distinct destination IPs — high on scans |
| 4 | `unique_dst_ports` | distinct dst ports < 1024 — high on port scans |
| 5 | `tcp_ratio`        | fraction of TCP traffic |
| 6 | `udp_ratio`        | fraction of UDP traffic |
| 7 | `avg_iat`          | mean inter-arrival time between packets |
| 8 | `bytes_per_sec`    | throughput over the window |

### The model

A fully connected autoencoder with a **9 → 6 → 9** architecture: a ReLU
encoder compresses the 9-D feature vector into a 6-D latent representation,
and a linear decoder reconstructs it. Trained only on normal traffic, so
normal windows reconstruct with low error and anomalies stand out.

### The threshold

```
threshold = max( P99,  Mean + 4·STD,  T_max · 1.5 )
```

computed on the reconstruction errors of a held-out normal validation set.
Combining a non-parametric cut-off (P99), a parametric one (Mean + 4·STD),
and a guard band above the largest normal error keeps false positives low.

## Quick start

### 1. Clone and install

```bash
git clone https://github.com/<your-username>/network-guardian.git
cd network-guardian

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Configure

```bash
cp config/config.example.yaml config/config.yaml
# edit config/config.yaml — set interfaces, hotspot SSID/passphrase,
# and (optionally) Gmail alert credentials using a Gmail App Password.
```

### 3. Try it without a Pi (demo)

Generate synthetic normal traffic, train, and you have a working model:

```bash
python3 src/generate_sample_data.py --rows 2000
python3 src/train.py --epochs 500
```

This writes `models/autoencoder.npz`, `models/scaler.npz`, and
`models/threshold.txt`.

### 4. Run on the Raspberry Pi (live)

Bring up the hotspot + NAT, then start the monitor (root is required for
raw packet capture):

```bash
sudo cp scripts/network-guardian-startup.sh /etc/network-guardian-startup.sh
sudo chmod +x /etc/network-guardian-startup.sh
sudo /etc/network-guardian-startup.sh

sudo venv/bin/python3 main.py
```

> Use `venv/bin/python3` under `sudo` so the virtualenv's NumPy/Scapy are
> used instead of the system Python.

Watch alerts and decisions:

```bash
tail -f logs/guardian.log
```

## Run at boot (systemd)

```bash
sudo cp systemd/network-guardian-net.service /etc/systemd/system/
sudo cp systemd/network-guardian.service     /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now network-guardian-net.service
sudo systemctl enable --now network-guardian.service
```

Adjust the paths in `network-guardian.service` if your project isn't at
`/home/arda/network-guardian`.

## Raspberry Pi one-time setup

Install the AP/DHCP packages and drop in the example configs:

```bash
sudo apt update
sudo apt install -y hostapd dnsmasq

sudo cp config/hostapd.conf.example /etc/hostapd/hostapd.conf
sudo cp config/dnsmasq.conf.example /etc/dnsmasq.d/network-guardian.conf
# edit both to match your SSID/passphrase and interfaces
sudo systemctl unmask hostapd
```

`wlan0` connects to your home router (uplink); `wlan1` is a USB Wi-Fi
adapter that broadcasts the `NetworkGuardian` hotspot. ESP32 devices only
support 2.4 GHz, so the hotspot uses `hw_mode=g`.

## ESP32-CAM (IoT device)

`esp32/CameraWebServer_NetworkGuardian.ino` is a trimmed AI-Thinker
CameraWebServer sketch. Set the SSID/password to match your hotspot, flash it
(GPIO0→GND for flash mode), and open the IP printed on the serial monitor
(115200 baud) to view the stream. Its traffic is what the detector learns and
monitors.

## Limitations & future work

- Detection works on **flow statistics**, not payloads, so traffic tunneled
  over HTTPS (port 443) can evade detection with low reconstruction error.
- A single network-wide model is used; **per-device** baselines would improve
  accuracy.
- Possible extensions: richer flow features (jitter, directional asymmetry),
  TLS metadata fingerprinting (JA3/JA3S), IP/ASN reputation, and a
  pcap-replay "demo mode" for offline testing.
